# 作业要求：设计企业财务问答 Agent 系统

## 任务与系统要求

设计并实现一个可复用的大模型 Agent。系统接收公司 CIK 和英文问题，自主选择查询 SQLite 数据库、检索本地年报、计算指标或核查结果，形成有依据的回答。**同一套系统应自动处理不同公司和问题，无需逐题人工修改程序、SQL 或答案。**

大模型应参与行动决策，根据已有证据和工具返回结果，决定下一步操作或何时结束。运行日志应能展示真实调用的工具、参数、结果及错误处理过程。

数据加载、格式转换和索引构建可以采用固定流程，也可将通用 SQL 或计算过程封装成工具，由模型按需调用。不要求多 Agent，也不要求每题都执行很多轮交互。预先固定每题全部步骤、仅让模型润色流水线结果，不符合本作业对 Agent 系统的要求。

## 提供什么，哪些由自己设计

提供六家公司的财务数据库、9 份年报正文、56 道问题和参考答案，以及输入输出协议和独立评测程序。文件用途见 [README.md](README.md)，年报文件目录见 `agent_workspace/data/filings/README.md`。

同学自行设计工具、数据组织、检索方式、prompt、Skill、memory、执行流程和结果检查。可先建立基础 Agent，再选择合适的方向优化。例如：

- 提前整理指标名称和口径，构建语义视图、查询模板或检索索引。
- 对年报按章节、公司与报告期组织，保留表格和来源位置，按需检索。
- 用参数化 Skill 复用指标定位、期间检查、跨期计算等过程。
- 用 memory 保存 train 阶段验证过的规则、失败经验和可复用方法。

不要求同时实现所有方向。重点说明所做设计如何帮助系统找到依据、减少错误或降低开销。

## 可使用的框架与 SDK

可使用 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai/deepseek-harness)、[Deep Agents](https://github.com/langchain-ai/deepagents)、[OpenAI Agents SDK](https://openai.github.io/openai-agents-python/)、[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) 或 [Google ADK](https://adk.dev/)。也可基于 [LangChain](https://github.com/langchain-ai/langchain)、[LangGraph](https://github.com/langchain-ai/langgraph) 构建，或直接使用模型 API 实现决策与工具调用循环。

使用现成 harness 时可以复用其交互循环，仍需完成数据适配、工具接入、可复用执行和实验分析。编程语言、内部接口、代码目录和运行命令不限；工具选择本身不作为评分依据。

## train 和 test 的使用规则

| 阶段 | 用法 |
|---|---|
| train：4 家公司、37 题 | 问题、参考答案和评测反馈可用于开发及优化，可反复试验；不要求训练模型参数 |
| test：2 家公司、19 题 | 固定代码、工具、prompt、Skill、初始 memory 和准备产物后，自动完成全部问题，再独立评分 |

数据库和年报提前全部发放，可以对全部公司资料做无标签预处理。不得利用 test 参考答案或评分反馈构建、修改方法，不得按 test 题号手工准备答案。

正式 test 每题从同一初始 memory 和准备产物开始，上一题产生的状态不带入下一题。先保存整批回答，再查看评分；查看反馈后的额外探索须另行标注，保留首次正式结果。全部材料公开，以上是诚信约定及公平比较要求。

## 文件使用与修改范围

以下路径相对 `agent_workspace/`：

| 文件或目录 | 使用方式 |
|---|---|
| 自建代码、配置、Skill、memory 目录 | 可自由设计和修改 |
| 自建 `artifacts/` 等目录 | 保存索引、映射、视图或派生数据库，并记录构建方法 |
| 自建 `outputs/` 等目录 | 保存实际生成的预测、日志和配置；不同实验另建目录，不手工修改结果 |
| `prompts/agent_system.txt` | 可修改，也可使用自己设计的提示词 |
| `data/`、`train/`、`test/` | 按上述规则读取，提供的原文件不改；派生材料另存 |
| `contracts/` | 外部输入输出协议固定，不修改 |
| `../evaluation_only/` | 评测程序、参考答案和评测提示词固定，仅独立评测时读取；作答 Agent 不得读取 |
| `../evaluation_outputs/` 等评分输出目录 | 保留评分结果；争议与分析另写报告，不供作答 Agent 检索 |

主实验使用提供的数据库和本地年报。若额外探索互联网资料，应单独报告，不混入主要实验对比。

## 输出、评测与提交

预测保存为普通 JSON 数组，每条只要求 `question_id` 和 `answer`，格式见 `contracts/prediction.schema.json`。查询、引用和计算过程另存于工具日志，不要求把它们加入预测协议，也无需提交模型隐藏思维链。

作答完成后，自行运行 `evaluation_only/evaluate.py`。检查器根据原问题、参考答案和已保存的回答，判定“支持”“矛盾”或“信息不足”并统计支持率。具体命令见 [评测说明.md](evaluation_only/评测说明.md)，整体操作见 [数据使用与作业完成流程.md](数据使用与作业完成流程.md)。

提交系统代码及运行说明、数据准备方法、prompt/Skill/memory 初始版本、train/test 预测、真实工具日志、运行配置与依赖版本、模型用量和耗时、独立评测结果及实验分析。比较基础方法与改进方法时，保持模型、数据、题目、工具预算、停止条件及检查器配置一致，分别记录预处理和逐题成本；无提升可如实分析。

本拓展作业最高加 10 分，按完成情况、系统设计、实验与分析综合评价，不设评分档位，也不把自动支持率直接换算为全部作业得分。
