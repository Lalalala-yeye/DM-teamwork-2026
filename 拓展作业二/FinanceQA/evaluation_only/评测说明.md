# 独立评测说明

先让自己的 Agent 完成作答并保存 predictions.json，再运行本目录的 evaluate.py。脚本将每题的原问题、原参考答案与回答交给检查器模型。回答作为 Context，不读取 Agent 代码或运行中的会话，不回调 Agent 修改答案。

## 使用哪些材料

- 问题：agent_workspace/train/questions.json 或 test/questions.json，每条仅有 question_id、company_cik、question。
- 原始参考答案：train/reference_answers.json 或本目录的 test_reference_answers.json。
- 评测 prompt：本目录的 evaluator_system.txt、evaluator_user.txt，内容逐字取自原始仓库的 TENK_CHAT_SYSTEM 和 TENK_CHAT_USER。
- 预测：普通 JSON 数组，每条至少包含 question_id 和 answer。其他自定义字段不参与评测；SQL、计算过程等保存在独立工具日志中。

评测使用统一的支持性判定，不设置逐题评分点或参考 SQL。预测格式检查只检查 JSON、题号和回答类型，不访问数据库、重跑 SQL 或核算计算过程。

## 判定和分数

检查器返回 context_quality、evidence_text、reasoning：

| context_quality | 含义 |
| --- | --- |
| CORRECT_INFO | 回答包含支持原答案的信息，可为部分或间接支持 |
| INCORRECT_INFO | 回答存在与原答案明确矛盾的信息 |
| INSUFFICIENT_INFO | 缺少与原问题和原答案相关的信息 |

采用原 prompt 的宽松判定，不要求精确数字、完整解释或复述答案。这里的 evidence_text 是从回答中摘录的支持判定文字，不是预先提供的标准 SQL，也不是数据库重跑结果。

support_percentage = CORRECT_INFO 题数 / 全部评测题数 × 100%。它表示支持率，不表示严格的完整答对率。incorrect_percentage 和 insufficient_percentage 按相同分母计算。报告同时给出 per_company 及其支持率平均值 average_support_percentage；题目汇总支持率与公司平均可能不同。

全部 test 题目保留在分母，缺失或空白回答归为 INSUFFICIENT_INFO，另行标记。重复或未知题号、回答不是字符串属于格式错误。服务失败或检查器响应解析失败标为 API_FAILED，单独报告 api_failed 及错误；该题仍在分母，与官方比例统计一致。有此类错误时 evaluation_complete=false，应修复接口后重新评测，再比较方法效果。

与原任务的区别：原任务把自主探索发现或最终总结作为 Context，本作业把针对明确问题的回答作为 Context；原脚本仅统计有日志的公司交集，本作业固定使用全部 test 题。通用判定 prompt 和三类标签沿用原版，不称为原榜单成绩。日志用于展示 Agent 的实际工具使用和结果来源，自动支持率不替代对实现与实验的分析。

## 实际命令

在 agent_workspace 中执行，预测文件路径按实际保存位置调整。输出路径须使用新实验目录，保留原始结果。

先检查预测文件格式，不调用模型，也不读取参考答案：

```bash
python3 ../evaluation_only/evaluate.py --split test --predictions outputs/test_v1/predictions.json --check-only --output ../evaluation_outputs/test_v1/check.json
```

仅导出实际评测请求，方便查看 prompt，不调用模型、不产生支持率：

```bash
python3 ../evaluation_only/evaluate.py --split test --predictions outputs/test_v1/predictions.json --export-requests ../evaluation_outputs/test_v1/judge_requests.json --output ../evaluation_outputs/test_v1/request_report.json
```

配置模型后进行评测：

```bash
export LLM_API_KEY='你的评测服务密钥'
python3 ../evaluation_only/evaluate.py --split test --predictions outputs/test_v1/predictions.json --judge-url https://你的服务地址/v1/chat/completions --model 你的评测模型 --output ../evaluation_outputs/test_v1/score.json
```

仅 --judge-url 模式调用模型。服务需支持 messages、temperature=0，并返回 choices[0].message.content；其中应为包含上述三个字段的 JSON。密钥从 LLM_API_KEY 读取，不写入结果。train 的用法相同，将 --split 设为 train；可用 --limit 检查少量 train 问题，test 始终评测全部题目。

比较不同方案时使用相同的检查器模型与 prompt。test 参考答案及导出的请求只供独立评测，不供作答 Agent 检索。完整流程见 [数据使用与作业完成流程.md](../数据使用与作业完成流程.md)。
