# 数据使用与作业完成流程

整体流程：**理解资料 → 在 train 上开发与优化 → 固定方法 → 自动完成 test → 独立评测 → 整理提交材料**。Agent 由同学自行实现，本说明不规定代码目录或统一作答命令。完整要求见 [TASK.md](TASK.md)。

## 1. 理解提供的资料

先阅读 `agent_workspace/data/schema.md`、`business_rules.md` 和 `companies.json`，了解数据库、指标口径及公司 CIK；再查看 `data/filings/README.md`，按公司和报告期找到年报文件。

数据库适合查询财务数值，年报补充产品、战略、风险和经营明细。每个问题只需获取相关证据，不必把所有报告一次交给模型。可以自行清洗 HTML、保留表格、划分章节并建立索引；这些准备产物另存，不改原数据。

`train/questions.json` 和 `test/questions.json` 每条只有 `question_id`、`company_cik` 和 `question`。根据原问题和资料中的日期确定期间，核对公司、指标、单位与重复披露，不自行补入未查到的事实。

## 2. 在 train 上开发和优化

train 共四家公司 37 题，参考答案位于 `train/reference_answers.json`。可用这些问题、答案和评分反馈理解任务、分析错误并调整系统；目标是形成可复用于其他公司和问题的方法。

可以先建立基础 Agent，再选择一个优化方向，例如：

- 从数据库及数据字典建立指标映射、检索目录、语义视图或索引。
- 用参数化 Skill 组织指标定位、口径检查、跨期比较等过程。
- 用 memory 保存 train 阶段验证过的规则、查询模式和失败经验。
- 改善模型选择工具、处理错误、检查结果及结束任务的方式。

代码、配置、Skill、memory 和准备产物由学生自行创建。

**不可使用 test 测试集的答案或测试反馈来设计方法！**

运行自己的系统，保存预测、真实工具日志及配置。预测遵循 `contracts/prediction.schema.json`；日志记录实际工具调用、参数、结果或结果文件、错误和耗时。代码、模型、prompt、预算和准备产物版本也应留档。

每次回答保存后，再用 `evaluation_only/evaluate.py` 独立评测；train 评测将 `--split` 设为 `train`。具体命令见 [评测说明.md](evaluation_only/评测说明.md)。根据 train 的参考答案、反馈和日志定位错误，再调整方法。

根据 train 的参考答案、评分反馈和工具日志分析错误，再调整方法并重新实验。比较基础方法与改进方法时，保持模型、题目、工具预算、停止条件及检查器配置一致，分别记录预处理和逐题成本。



## 3. 固定方案并完成 test

固定代码、工具、prompt、Skill、初始 memory 和准备产物，使用同一系统自动回答全部 19 道 test 问题。每题从相同初始状态开始，题内状态不带入下一题。

**不得使用 test 参考答案或评分反馈设计方法，也不得逐题人工写 SQL、修改程序或准备答案。** 作答阶段不读取 `evaluation_only/` 和评分输出。先保存整批预测、日志及运行配置，再进入独立评测。

## 4. 独立评测 test

具体脚本、命令、服务配置和结果说明见 [evaluation_only/评测说明.md](evaluation_only/评测说明.md)。先检查预测格式，再使用与 train 相同的检查器配置评测全部 test 题目。

格式检查不判断正确性；导出请求也不产生模型分数。检查器比较已保存的回答与问题、参考答案，不回调 Agent 修改结果。评分输出建议放在包根目录的 `evaluation_outputs/`，不供作答 Agent 检索；导出的请求包含参考答案，也应按同样规则处理。

## 5. 整理报告与提交

说明系统如何选择工具、获取证据、处理错误，以及采用了哪些优化。对比基础方法和改进方法的效果、模型用量与耗时，分别记录数据准备和逐题成本，并保持对比配置一致。

提交系统及运行说明、准备产物及其构建方法、初始 prompt/Skill/memory、预测、工具日志、配置与版本、独立评测结果和实验分析。
